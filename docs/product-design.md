# AI 情报采集 Bot —— 产品设计思路

> 一份面向产品经理的产品设计文档，说明「为什么做」「给谁看」「采什么」「怎么筛」「产出什么」。

---

## 1. 产品定位

**一句话**：面向互联网公司业务团队的 AI 行业情报产品，把每天爆炸式的 AI 信息，压缩成一份「可读、可落地、有优先级」的每周周报。

**核心价值主张**：不是「信息更多」，而是「噪声更少、信号更准」。团队不用自己刷 RSS、翻论文、追 KOL，就能知道「本周 AI 领域发生了什么、对我有什么影响、我能抄什么作业」。

**产品形态**：飞书群机器人，每周定时推一张结构化卡片。后台是 GitHub Actions 定时任务 + DeepSeek LLM。

---

## 2. 目标（Goals）

| 目标 | 说明 | 衡量方式 |
|---|---|---|
| **降噪提纯** | 从每周 ~400 条原始内容中，精选出有影响力的少量内容 | 周报条目数控制在 30-40 条 |
| **领域对齐** | 内容聚焦「AI 产品经理、电商/导购、评测、应用落地」，而非纯前沿研究 | 领域相关度评分 |
| **可落地** | 每条信息尽量给「应用启示」，让读者知道能做什么 | 应用启示字段覆盖率 |
| **零维护成本** | 全自动运行，无需人工干预 | GitHub Actions 定时 + 免费额度 |

**非目标**（明确不做）：不做实时快讯、不做个性化订阅、不做多轮交互问答、不追求「全量覆盖」。

---

## 3. 目标用户（对象）

**核心用户**：互联网公司业务团队，以 **AI 产品经理** 为主，非技术背景居多。

| 用户画像 | 需求 | 对应设计 |
|---|---|---|
| AI 产品经理 | 找灵感、找方法、找竞品动态 | 应用启示、产品方法论、工具推荐 |
| 业务/运营 | 想知道 AI 能否提效、怎么落地 | 应用落地案例、业务提效数据 |
| 技术负责人 | 技术视野，但不看纯论文 | 前沿技术（压缩为最热门的） |
| 老板/决策层 | 快速了解行业大事件 | 本周必读 Top 5-8 |

**关键设计原则**：所有内容都要「翻译成人话」—— 每条配「通俗解读」（80字内）+「应用启示」，拒绝术语堆砌。

## 4. 信源体系（Sources）

四类信源，按「信号密度」分层：

### 4.1 榜单/热门源（🔥 高信号，新增核心）

直接接入信源内部的「热度排序」，而非时间流：

| 源 | 排序依据 | 类型 |
|---|---|---|
| Hacker News 热门 | 社区投票 score | 英文科技热帖 |
| HuggingFace 论文榜 | upvotes | 热点论文 |
| HuggingFace 趋势模型 | trendingScore | 热门开源模型 |
| 极客公园 本周热门 | 编辑精选 | 中文 AI/科技 |
| 掘金 热榜 | hot_rank + 阅读/点赞 | 中文开发者社区 |
| 36氪 热榜 | 编辑精选热门 | 中文科技圈热文 |

### 4.2 RSS 源（28 个，广度覆盖，已清理死源）

- **国内媒体**：量子位、少数派、极客公园、雷锋网、InfoQ、爱范儿
- **海外官方博客**：OpenAI、DeepMind、HuggingFace、NVIDIA、Anthropic
- **海外媒体**：TechCrunch、The Verge、MIT Tech Review、Wired、ZDNet、Nature
- **学术**：ArXiv cs.AI、cs.CL（大幅压量，热点论文由 HF 论文榜覆盖）
- **商业/电商**：Retail Dive、Modern Retail、MarTech（贴合电商场景）
- **产品工具**：Product Hunt、GitHub Blog、GitHub Changelog

### 4.3 网页采集（6 个，补充无 RSS 的源）

36氪 AI、机器之心、Anthropic、Stability AI、GitHub Trending（周榜+Python日榜）。

### 4.4 Twitter/X KOL（17 个）

产品管理（shreyas、lennysan、wes_kao）、AI 领军（sama、ylecun、AndrewYNg）、AI 工程、AI 产品/工具。三级降级：RapidAPI → Playwright → 跳过。

### 4.5 微信公众号（Playwright 渲染搜狗搜索，10 组关键词）

通过搜狗微信搜索自动检索 AI 相关关键词，Playwright 渲染页面提取标题和摘要。搜狗有 IP 级反爬，本地可能被拦截，GitHub Actions 上 IP 不同通常可通。

覆盖领域：AI 产品经理、AI 导购、AI 电商、AI 评测、AI 应用案例、AI Agent、AI 智能体、AI 大模型、AI 工具、AI 行业趋势。

**电商竞对监控不在微信单一渠道**，而是通过领域关键词系统横跨所有信源（RSS、榜单、网页、Twitter、微信）过滤。

**信源可信度分级**：T1（官方一手）→ T2（国际媒体）→ T3（国内媒体）→ T4（社交媒体，需交叉验证），作为评分权重。

## 5. 筛选标准（核心：三层漏斗）

这是产品的「灵魂」。三层漏斗从「粗筛」到「精筛」：

```
┌─────────────────────────────────────────────┐
│ ① 领域相关性（关键词信号，不淘汰，交给 AI 判断）       │
│    关键词命中 = 加分提示，不命中 = 不淘汰           │
│    ↓                                        │
│ ② 热度信号（榜单源 + 交叉验证）                    │
│    榜单源天然高热度；≥2 源交叉验证加分              │
│    ↓                                        │
│ ③ AI 五维质量评分                               │
│    credibility + freshness + applicability    │
│    + insight + relevance                      │
└─────────────────────────────────────────────┘
```

### 5.1 领域相关性

**关注领域关键词**：

| 优先级 | 领域 | 关键词示例 |
|---|---|---|
| ⭐⭐⭐ | AI 导购/电商 | 导购、推荐、电商、商品、转化、选品、客服 |
| ⭐⭐⭐ | AI 评测 | 评测、benchmark、基准、榜单、模型对比 |
| ⭐⭐⭐ | AI 产品经理 | 产品经理、产品设计、增长、用户体验、方法论 |
| ⭐⭐⭐ | AI 应用落地 | 案例、落地、ROI、提效、赋能、降本 |
| ⭐⭐⭐ | AI Agent/业务提效 | Agent、智能体、工作流、Copilot、自动化 |

**防误杀设计**：关键词只做「加分信号」，不淘汰。AI 能理解语义，换种表达仍能识别。

### 5.2 AI 五维评分（1-10 尺度，含分布约束）

```
combined = credibility×0.20 + freshness×0.10
         + applicability×0.30 + insight×0.20 + relevance×0.20
```

- 各维度 **1-10 分**，要求 AI「拉开差距，不堆在中间值」
- **分布约束**：9-10 分只给极少数最重磅内容（约 10% 以内），4 分以下给明显低质内容
- **relevance（领域相关度）**：纯论文/架构细节 = 1-3 分；落地案例/产品方法/业务数据 = 7-10 分
- 输出后自动 **类目归一化**，消除 AI 返回短名/错 emoji 导致的类目拆散问题

### 5.3 类目优先级 + 量级

| 优先级 | 类目 | 周报条目数 | 口径 |
|---|---|---|---|
| ⭐⭐⭐ | 🛒 电商平台AI动态 | 5-8 | 竞对平台的 AI 新功能/动作 |
| ⭐⭐⭐ | 🛠️ AI工具与产品 | 5-8 | 热议工具、评测、PM 能用上的 |
| ⭐⭐⭐ | 🏭 行业AI应用 | 3-5 | 非电商行业 AI 落地案例 |
| ⭐⭐⭐ | 🎙️ KOL洞察 | 3-5 | 关键 KOL 实质观点 |
| ⭐⭐ | 💼 企业AI提效 | 2-3 | 企业内部 AI 提效方案 |
| ⭐⭐ | 🧠 大模型动态 | 2-3 | 只留最重大的发布/突破 |
| ⭐ | 🔬 前沿技术/论文 | 1-3 | 只留最热门且可落地的 |

## 6. 产出结构（Output）

飞书卡片，固定模块：

| 模块 | 内容 | 数量 |
|---|---|---|
| 🔥 **本周必读** | 对 PM/互联网行业最有影响力的 | 5-8 条 |
| 📂 **分类详情** | 按 7 类目组织（电商平台AI动态、AI工具、行业AI、企业提效、KOL、大模型、前沿技术） | 各类目见上表 |
| 💡 **应用启示** | 对业务的启发 + 为什么现在关注 | 3-5 条 |
| 🛠️ **值得关注** | 工具/项目 + 描述 + 链接 | 5 条 |
| 📊 **统计** | 采集数、精选数、分类分布 | 1 行 |

**每条信息的三字段格式**：

```
📎 标题（可点链接）
💬 通俗解读（80字内，人话）
💡 应用启示（能做什么）
```

## 7. 技术架构

```
GitHub Actions (每周三 9:00 北京时间)
  └─ python main.py
       ├─ 采集层 collectors/
       │    ├─ trending_collector  (榜单，第0步)
       │    ├─ rss_collector       (38源)
       │    ├─ web_collector       (6源)
       │    └─ twitter_collector   (17 KOL)
       ├─ 处理层 processor.py
       │    ├─ 去重 (URL + 标题相似度)
       │    ├─ 交叉验证 (标题 Jaccard)
       │    ├─ AI 五维评分 (DeepSeek)
       │    └─ 周报生成 (DeepSeek)
       ├─ 推送层 reporter.py (飞书卡片)
       └─ 存储层 storage.py (SQLite + FTS5 全文搜索)
```

- **LLM**：DeepSeek API（`deepseek-chat`），两条处理（逐条评分 + 汇总周报）
- **存储**：SQLite + FTS5，供后续 @bot 答疑检索
- **部署**：GitHub Actions 免费额度（每次约 10 分钟）

## 9. 关键设计权衡（Trade-offs）

| 权衡点 | 选择 | 理由 |
|---|---|---|
| 关键词 vs AI 判断 | 关键词做信号，AI 做终判 | 避免关键词误杀 |
| 前沿研究 vs 应用落地 | 前沿压缩到 2-3 条 | 用户核心是 PM，不是研究者 |
| 全量 vs 榜单 | 榜单优先 + RSS 补广度 | 榜单信号密度高，RSS 兜底 |
| 中文 vs 英文 | 双语并行 | 中文热榜 + 英文前沿 |
| 定时 vs 实时 | 每周三定时 | 周报形态，非快讯 |
